The headline feature is viewing several clips as one: select shots in the playlist and review the edit and the cuts between them, just like in RV — all the way to exporting the sequence as a single file. Alongside it come scrub audio for lip-sync, hotkeys for every drawing tool, settings that no longer reset, and a new visual HTML user manual. Clips as one sequence — like in RV Check the edit without assembling it in a video editor. Select clips in the playlist with Ctrl or Shift and press the As one sequence button at the bottom of the playlist. With fewer than two selected, the whole playlist goes in, in playlist order. One timeline for the whole sequence: cuts show as yellow ticks, frame numbers run straight through, and the current clip's name appears right on the frame (the N button). Shift+→ and Shift+← jump to the next and previous cut. Playback, Loop, In/Out points, scrubbing and scrub audio all work across cuts. Clips can differ: another resolution is letterboxed, a clip without sound plays silence, and variable-frame-rate screencasts stay in sync. A clip with a different fps is conformed to the sequence — the program warns you. Drawings and bookmarks are remembered per clip and its own frame: reorder the clips or open a clip on its own — the annotations stay in place. The sequence is saved into the .fcmd project with the position and segment. If a clip has gone missing from disk, the sequence is rebuilt from the rest. The sequence runs in the Normal mode; Split, 2x2 and other modes close it. Turn the button off and the clip under the playhead stays in the player, on the same frame. Exporting a sequence as one file Send the edit for review as a single video, not a pile of files. The regular Export (Ctrl+E) in sequence mode renders the In/Out segment across every cut into one MP4 with the sequence audio. The frames are exactly what the player shows, at the first clip's resolution. A JPEG sequence is numbered by sequence frames. Cancel stops the export and deletes the unfinished file. Scrub audio for lip-sync Hear a frame's sound when you move through the video by hand. The sound-wave button next to the volume, or Shift+S: every frame step plays a short slice of that frame's audio. It sounds when stepping with the arrows and dragging on the timeline or right on the frame; normal playback, jumps and bookmark navigation stay as before. Right-click the button to choose the slice length: 1, 2 or 3 frames. Works in Normal, Split and 2x2 modes (the active panel is voiced); the switch is shared and remembered. Off by default. Hotkeys for drawing Annotate without trips to the toolbar. 1–8 — pencil, vanishing ink, line, arrow, rectangle, circle, triangle, text. A digit turns drawing on by itself. "-" and "=" — line width or font size. Delete clears the frame's annotation immediately, without a prompt; Shift+Delete clears all frames, with confirmation. Both can be undone with Ctrl+Z. Button tooltips show the current keys; every key can be reassigned on the Hotkeys tab. Stability and convenience Settings no longer reset. The settings file moved to the user profile folder (%APPDATA%\FramesCommander): it is always writable, even when the program sits in Program Files, and a new version unpacked in place of the old one picks up your hotkeys. Old settings migrate automatically on first launch. A failed read no longer wipes the settings. Per-file bookmarks, just like drawings. The update is recommended for all users of version 1.18. 2026-08-29 🔧 FuryNotesv1.3.0 Nearly all of this release grew out of one message. Someone built a note full of links to files on their own disk, ran into a few rough edges, and wrote in about them. Here is what came of it. The program keeps earlier versions of your text. A note here saves itself, so there is never a "did I save that?". For the same reason there was never an unsaved version to fall back on either: delete a paragraph, look away for a second, and it is gone from the file; close the program and the undo stack goes with it. FuryNotes now quietly puts copies of the text aside. When a copy is taken: — before you start changing a note. The first keystroke after you open it is the last moment the old text exists anywhere, so that is when the copy is made. Merely opening a note and reading it copies nothing — otherwise one pass through the library would leave a copy of everything you had glanced at; — while you write — at most one copy every ten minutes; — the moment a note is deleted, whatever the clock says. Delete a folder and every note inside it is copied. Getting one back: right-click any note or folder in the tree → "History…". On the left is every note that has copies kept, deleted ones included — they are marked, and they come back exactly the same way. On the right are its copies by date and the text of whichever you pick, so you can be sure you are taking the right one. "Restore this copy" writes it back into the note. Restoring destroys nothing. What the note says right now is kept as another copy first, so a restore can itself be undone. A note that is gone altogether is written back where it used to live. The copies are ordinary text files — no database, no format of our own. They sit in a ".furynotes-history" folder beside your notes and mirror them: "Work\ideas.md" has its copies in ".furynotes-history\Work\ideas.md\", one file per copy, named by the date and time. Explorer and Notepad open them; FuryNotes is not needed to read them. Same rule as the notes themselves being plain .md files: a lifebelt only one program can open is a poor lifebelt. Twenty copies of each note are kept, and older ones drop off as new ones arrive. A copy identical to the previous one is never written — change nothing and nothing is put aside. A renamed or moved note takes its copies with it. This does not replace the Recycle Bin. Deleting still sends the file itself to the Windows Recycle Bin, and that is the first place to look. The copies are for the day the Bin has been emptied. All of it can be switched off: settings → "Keep earlier copies of the text". It is on as the program ships, because a safety net nobody switched on is not a safety net. Search finds a note by its name, not only by its text. Ctrl+F now matches what a note is called as well. Those matches come first, on a row of their own: the name itself is highlighted, and a line of the note is shown underneath for context. Enter opens it at the top and highlights nothing — what matched was not a word inside the note but what the note is called. There is nothing to switch: names and text are always searched together. A note still on its date-stamped filename is called by its first line, in the tree and in the search alike, so looking for that finds it either way. A disagreement was fixed on the way. The search used to label a result with the note's first line even when the note had been given a name — a note called "Shopping" read as "Shopping" in the tree and as its first line in the search. Both lists now call it the same thing. Renaming, with a double click. Double-click a note and its name opens for editing right there in the row. Enter keeps the new name, Esc leaves it as it was. F2 and right-click → "Rename" do the same thing, for a folder as well: a folder was already edited in its row while a note needed a separate little window, which made the commoner of the two the slower one. Double-clicking a folder still opens and closes it — that gesture is taken there and stays as it was. Rename a folder with F2 or the menu. A rename still carries the pin, favourite, colour and icon over to the new name — and now the kept copies of the text as well. A link says how to open it. A link opens on Ctrl+click. It always did, but there was nowhere to learn that: the address is hidden, so on screen a link is just a coloured word. The person who built a page of local links concluded they simply did not work. Now: rest the pointer on a link and a tooltip shows where it points and reminds you about Ctrl+click. Or right-click it — "Open link" is the first thing on the menu, above Cut. Fixed: stars inside a link. Ctrl+B on a word inside a link wrote two pairs of stars, and they stayed there in the middle of the line — the word never came out bold. And if you started removing them by hand it was easy to catch the closing bracket, at which point the link stopped being a link and its address showed up in plain sight. The cause was that a link swallowed its own label whole, so formatting inside it was not recognised at all. It is now: Ctrl+B, Ctrl+I and Ctrl+Shift+X work on a link's words like anywhere else, and the stars hide themselves as usual. The address is still protected — underscores and stars inside a path do not format anything. Smaller things. Renaming a folder no longer breaks Favourites for the notes inside it. Before, those shortcuts pointed at nothing afterwards and quietly dropped off the list. The manual (docs\manual) has been updated: a new "Note history" section, additions to "Links", "Search" and "Renaming", and a 1.3.0 card in "What's new".
