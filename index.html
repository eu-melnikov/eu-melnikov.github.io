2026-08-29 🔧 FuryNotesv1.3.0 Nearly all of this release grew out of one message. Someone built a note full of links to files on their own disk, ran into a few rough edges, and wrote in about them. Here is what came of it. The program keeps earlier versions of your text. A note here saves itself, so there is never a "did I save that?". For the same reason there was never an unsaved version to fall back on either: delete a paragraph, look away for a second, and it is gone from the file; close the program and the undo stack goes with it. FuryNotes now quietly puts copies of the text aside. When a copy is taken: — before you start changing a note. The first keystroke after you open it is the last moment the old text exists anywhere, so that is when the copy is made. Merely opening a note and reading it copies nothing — otherwise one pass through the library would leave a copy of everything you had glanced at; — while you write — at most one copy every ten minutes; — the moment a note is deleted, whatever the clock says. Delete a folder and every note inside it is copied. Getting one back: right-click any note or folder in the tree → "History…". On the left is every note that has copies kept, deleted ones included — they are marked, and they come back exactly the same way. On the right are its copies by date and the text of whichever you pick, so you can be sure you are taking the right one. "Restore this copy" writes it back into the note. Restoring destroys nothing. What the note says right now is kept as another copy first, so a restore can itself be undone. A note that is gone altogether is written back where it used to live. The copies are ordinary text files — no database, no format of our own. They sit in a ".furynotes-history" folder beside your notes and mirror them: "Work\ideas.md" has its copies in ".furynotes-history\Work\ideas.md\", one file per copy, named by the date and time. Explorer and Notepad open them; FuryNotes is not needed to read them. Same rule as the notes themselves being plain .md files: a lifebelt only one program can open is a poor lifebelt. Twenty copies of each note are kept, and older ones drop off as new ones arrive. A copy identical to the previous one is never written — change nothing and nothing is put aside. A renamed or moved note takes its copies with it. This does not replace the Recycle Bin. Deleting still sends the file itself to the Windows Recycle Bin, and that is the first place to look. The copies are for the day the Bin has been emptied. All of it can be switched off: settings → "Keep earlier copies of the text". It is on as the program ships, because a safety net nobody switched on is not a safety net. Search finds a note by its name, not only by its text. Ctrl+F now matches what a note is called as well. Those matches come first, on a row of their own: the name itself is highlighted, and a line of the note is shown underneath for context. Enter opens it at the top and highlights nothing — what matched was not a word inside the note but what the note is called. There is nothing to switch: names and text are always searched together. A note still on its date-stamped filename is called by its first line, in the tree and in the search alike, so looking for that finds it either way. A disagreement was fixed on the way. The search used to label a result with the note's first line even when the note had been given a name — a note called "Shopping" read as "Shopping" in the tree and as its first line in the search. Both lists now call it the same thing. Renaming, with a double click. Double-click a note and its name opens for editing right there in the row. Enter keeps the new name, Esc leaves it as it was. F2 and right-click → "Rename" do the same thing, for a folder as well: a folder was already edited in its row while a note needed a separate little window, which made the commoner of the two the slower one. Double-clicking a folder still opens and closes it — that gesture is taken there and stays as it was. Rename a folder with F2 or the menu. A rename still carries the pin, favourite, colour and icon over to the new name — and now the kept copies of the text as well. A link says how to open it. A link opens on Ctrl+click. It always did, but there was nowhere to learn that: the address is hidden, so on screen a link is just a coloured word. The person who built a page of local links concluded they simply did not work. Now: rest the pointer on a link and a tooltip shows where it points and reminds you about Ctrl+click. Or right-click it — "Open link" is the first thing on the menu, above Cut. Fixed: stars inside a link. Ctrl+B on a word inside a link wrote two pairs of stars, and they stayed there in the middle of the line — the word never came out bold. And if you started removing them by hand it was easy to catch the closing bracket, at which point the link stopped being a link and its address showed up in plain sight. The cause was that a link swallowed its own label whole, so formatting inside it was not recognised at all. It is now: Ctrl+B, Ctrl+I and Ctrl+Shift+X work on a link's words like anywhere else, and the stars hide themselves as usual. The address is still protected — underscores and stars inside a path do not format anything. Smaller things. Renaming a folder no longer breaks Favourites for the notes inside it. Before, those shortcuts pointed at nothing afterwards and quietly dropped off the list. The manual (docs\manual) has been updated: a new "Note history" section, additions to "Links", "Search" and "Renaming", and a 1.3.0 card in "What's new". 2026-08-22 ⚙️ BackDropv1.6 Over five versions BackDrop stopped being only a cover: it now photographs the screen as well — five ways to capture, each on its own system-wide key, and every one of them works while the program is nowhere to be seen. It lives in the tray, comes up with Windows and speaks Russian as well as English. Five ways to photograph the screen. Settings, Capture tab. Each way has its own key field and its own line in the tray menu: Alt+1 — a piece of the screen, a frame you drag by hand Alt+2 — the window in front Alt+3 — the screen under the pointer Alt+4 — every monitor at once, in a single picture Alt+5 — the area you set aside, a frame left standing on screen The keys are yours to change, and any of them can be left empty. The key is registered with Windows itself, so it answers over any program and with BackDrop away in the tray: take the picture, save it, and the program never showed itself at all. A piece of the screen, framed by hand. Alt+1 freezes the screen, so a notification that pops up or a video playing below cannot spoil the shot halfway through. Drag the frame, adjust it by its corners and sides, move the whole thing, or start again by dragging outside it. Three buttons sit under the frame: copy (Enter or Ctrl+C), save (Ctrl+S), close (Esc). The screen is no longer dimmed while you frame — all that is left is the dashed border, the white handles and the size of the selection in pixels. Marking up the picture before it leaves. The bar under the frame carries a set of pens: freehand, line, rectangle, circle, arrow and text, with a colour swatch, undo and a wipe beside them. An arrow and a caption can go on before the picture goes anywhere: what you see drawn is exactly what reaches the clipboard or the file — the ink is clipped to the frame. A minus and a plus set the size: line width 1 to 20 with a pen or a shape, font size 8 to 72 with the text tool; hold a button down and the value walks the range. The colour and the width here are the same pen as the one on the canvas, and the choice survives a restart. A tool in hand takes the mouse; a second click on it, a right-click or Esc puts it down and hands the frame back. Quick captures: the window, a screen, every screen. Alt+2, Alt+3 and Alt+4 ask nothing at all. The file goes straight into the folder named on the Capture tab, under the name and format you chose, with the next number that name has not used — no frame, no dialog, and deliberately no word of confirmation: a message after every capture wears out its welcome by the tenth one. The window in front is cut to what the window actually draws, without the invisible border Windows keeps around a resizable window — the strip of desktop around every shot is gone. Every monitor comes out as one picture, laid out the way the screens sit on the desk. The tray menu grew a Capture submenu listing all five with the key each answers to, plus entries that open the pictures folder and put the path of the last picture on the clipboard. The area you set aside (Alt+5). An area you set up once and photograph as many times as you like. The first press puts a frame on the screen; every press after that takes what is inside it. Draw it once around the thing you keep needing a picture of — a log window, a viewport, a corner of a chat — then go back to work, and the key takes the same rectangle every time. The middle of the frame is see-through: clicks inside land in whatever you are actually working in, and only the border and the bar above the frame take the mouse. The bar shows the size of the picture to come and carries two buttons — the camera takes it, the x puts the area away, and the x asks first. The border is drawn outside the piece being photographed, so the frame is never in its own picture and the screen does not even flicker. Where the frame stood is remembered: put it away, ask for it again, and it comes back to the same place — and it comes back on its own at the next start, if that is how you left it. The name, the number and the folder. The name and format of saved pictures live on the Behavior tab: "screenshot" to begin with, PNG or JPG, and JPG quality is a setting now instead of a number baked into the code. A new picture takes the number after the highest, not the first free one — in a folder that had had pictures deleted out of it, the newest file used to land in the middle of a listing sorted by name, which looked exactly like a capture that had not happened. The checkbox "Say in the name what the picture is of" gives each kind of capture its own word and its own count — screenshot_front_app_1, screenshot_scr_1, screenshot_allscrn_1, screenshot_area_1, screenshot_region_1 — so the kinds stop interleaving in the folder. Off to begin with; turning it on leaves saved files alone. A name the folder already has is now a proper question: replace it, keep both, or cancel. Keeping both writes "name (2).png" beside it, Explorer style. The save picture window. The save button — on the toolbar and under the selection frame both — remembers the last thirty folders and shows them as a list in a window of its own. A double click on a folder, or Enter on the selected line, writes the file there under the automatic name; "Browse..." opens the ordinary file dialog for a folder that is not on the list, or a name of your own. The window opens centred on what is being saved, and it is not modal, so the frame behind it can still be adjusted without closing the question: the picture is cut when you pick the folder, not when you press the button. A folder on a drive that is not plugged in today simply drops off the list. Ctrl+S still goes straight to the file dialog. The picture, or a link to it, on the clipboard. A saved picture can leave one of two things on the clipboard: the picture itself, for pasting into a chat, or the path to the file it just wrote, for pasting a link where the pixels will not go. Never both — there is one clipboard, and a picture put on it would wipe the path, so the two checkboxes in Settings clear each other. It holds for every save now, however it was asked for: a quick capture on its key, a folder picked in the save window, or the file dialog. Living in the tray. While BackDrop is running it keeps an icon in the notification area. A left click puts the program away, or brings it back exactly as it was: the same mode, the same drawings, the same place. A right click opens the menu: show or put away, see-through mode, the captures, the pictures folder, the path of the last picture, start with Windows, Settings, About, and Quit — the one way out for good. The x on the floating palette puts BackDrop in the tray without ending it, and the window's own close button does the same; the checkbox for that is on by default, and clearing it makes the button end the program as it used to. Starting the program twice is now hard to do: a second launch wakes the copy already running and bows out. Starting with Windows. The Startup tab, "Launch BackDrop when I log in". No administrator rights are needed, the entry shows up in Task Manager alongside every other startup program, and clearing the checkbox removes it. On the same tab, what the program greets you with: the palette in see-through mode over a live desktop with clicks passing through (the default), waiting in the tray with nothing on the screen at all though the capture keys still work, or the ordinary window for anyone who wants the old start. That choice used to apply only to an automatic start; it applies to every start now. Hotkeys of your own. The field catches whatever you press, and Clear leaves a capture mode with no key at all. A combination needs at least one modifier — a bare letter would be taken away from every other program on the computer; PrtSc and Pause are the exceptions. If another program already holds the combination, BackDrop says so: a line with the reason sits under the field on the Capture tab, and the tray menu writes "key taken" beside the mode. Such a key used to say nothing — it looked like a working one in Settings and simply did not appear in the menu. A Russian interface. The whole program speaks Russian: windows, settings, tooltips, the tray menu — and the user manual comes in both languages. The language is picked on the Behavior tab and takes effect at the next start. It is a written translation rather than a literal one, with the program and the manual agreeing on the same words throughout. Fullscreen leaves the taskbar alone. The window used to fill the whole monitor, and Windows answered by taking the taskbar off the screen. BackDrop now covers the work area — everything but the taskbar: the clock, the tray and the way to your other programs stay in sight. What gets hidden is the desktop, not Windows itself. The floating palette stopped jumping along with it: the restore-window button now stands on the palette in both modes, both modes measure the palette's parking place with the same ruler, and a palette parked at the bottom stops just above the taskbar instead of lying over it. The Toolbar tab gained an "Edge gap" slider, 0 to 20 pixels. Silence when it worked. A save and a copy no longer announce themselves. The file is in the folder and the picture is in the clipboard; a message on top of that is one more thing to read and one more thing that can land in a recording, which is what the program is for. What is left speaks only when something failed or was refused. Fixed. The save button under the selection made the screen flash and did nothing else: the list of recent folders was a drop-down menu, and the menu closed itself the same instant. It is a window now. Turning down the save dialog cost you the whole selection — the frame closed before the dialog opened. It now comes back with the selection intact. The capture key fired over an open dialog too. The frame then took neither clicks nor Escape, and the only way out was the task manager. Pressing the key twice made two frames on top of each other and left a still picture on the screen that answered to nothing. Quit in the tray menu ended the program instantly, without asking — the cover vanished, and the session's drawings with it. A minimized window would not come back from the tray: a click on the icon offered to put the program away rather than show it. Two copies launched at the same moment both carried on — two tray icons and two writers to one settings file. With no notification area on the desktop, the program hid into nothing: no window, no icon, no way to get it back. A capture picked from the tray menu could catch the menu itself: it was dismissed, but the screen underneath had not been redrawn yet. In see-through mode the folder-picking window made it into the saved picture. The Russian interface translated the author's signature in the window title; it is "(by e.ov)" everywhere now. The About window has been rewritten — it still described the program as a cover and nothing else. A note can be given a picture, and it stands in front of its name in the tree. Fifty-odd to choose from: an aeroplane, books, a guitar, a lightbulb, a rocket, a heart, smileys, music notes, a calculator and so on. The point is simple — in a column of similar names the eye finds a shape faster than it reads words. Right-click a note → "Icon", then the grid; one click and it is there. "No icon" in the same menu takes it off. The icon belongs to the note: rename it or move it to another folder and the icon goes along, the way a colour and a pin already do. It also travels to another computer — only the icon's name is kept beside the note, and the picture itself is inside the program at both ends. A colour of its own for each icon. Under the grid are ten neon colours. The one you pick paints that icon, not all of them, so you can tell things apart: work in blue, home in green, urgent in red. "Default colour" puts it back. The colour knows about the theme. What is stored is really the hue, and how light to draw it is worked out again for the background in use. That is why the same note looks right on the dark theme and on the light one — a vivid yellow-green that glows on black would otherwise simply vanish on white. Neon and a glow, if you want them. Two tick-boxes in the settings. "Neon note icons" paints every icon that has no colour of its own in your accent colour. "with a glow" lights a halo around them — the neon outline itself. Both are off as the program ships: this is a taste, not the way the program has to look. The glow is drawn into the empty margins around the icon, so not one name in the tree moves by a single pixel. Back and forward, like a browser. Two arrows on the toolbar, and Alt+← / Alt+→, walk the notes you have already opened. The side buttons on your mouse do the same. The trail follows the notes rather than the files: a note that has since been deleted is not a dead end — that step is skipped and the next one taken — and a renamed note keeps its place in the chain. An arrow with nowhere to go is drawn faded, so you can see at a glance whether there is anything behind you. You can see which note is open. A caret now stands in front of its row and its name is a shade brighter than the rest. Before this, coming back to the program meant working out where you had left off. A pinned note keeps its bookmark at the same time — the marks no longer push each other out. Two gestures on a folder instead of one. The folder's icon opens and closes it, the name only selects it, and a double click on the name opens it. Before, a click anywhere on the row toggled the folder, so it could not be chosen as the place for a new note without flapping open on the way. Two vertical stripes down a selected row went at the same time: one was ours, the other was Windows painting its own accent colour, which answered to nothing in the theme. A new manual, one for everything. Instead of a stack of per-version documents there is now a single page: docs/manual. English and Russian switch with a button, and it has contents down the side and a search across the text. A "What's new" section carries a card per version, so a minute is enough to see what has appeared since you last updated. And the formatting section opens with a cheat sheet: one picture showing every kind of formatting at once, where each line names the keys that made it. Smaller fixes. Animation Loader Limited

Animation Loader Limited is a script for working with a library of FBX animations in Maya. It loads clips into the scene one after another along the timeline, writes them back out to files, keeps several libraries at once, helps you add new animations to them, and watches over file versions — almost like Perforce, only there is nothing to set up. The scene itself records which clip covers which frames and which file it came from. Free, MIT, shipped as source. Nothing but Maya required.
